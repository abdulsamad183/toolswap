# M1 clean SQLite replay

M1 demonstrates that the benchmark can start from a known database, run a replacement, and grade the resulting state and response. The bundled `oracle` policy is a fixed sequence of trusted tool calls. The evaluator checks the final SQLite snapshot and the reported result independently.

## Run the demonstration

From the repository root:

```sh
uv run --locked toolswap scenario run --manifest examples/m1/inspection.yaml
uv run --locked toolswap scenario run --manifest examples/m1/replacement.yaml
uv run --locked toolswap scenario run --manifest examples/m1/replacement.yaml
```

All three calls should print `Outcome: PASS`, an artifact directory, and the state and trace hashes. The two replacement calls should print the same hashes and directory. The runner starts a fresh SQLite database on every invocation and checks any existing bundle against the new evidence.

## Read the evidence

| Artifact | What it shows |
| --- | --- |
| `resolved_config.json` | The exact scenario version, policy, and seed used. |
| `trace.jsonl` | Ordered tool results, the final response, and the evaluator's verdict. Each event has a logical sequence number, an integrity hash, and before and after state hashes. |
| `effects.jsonl` | Committed writes, their original request keys, and their state references. |
| `response.json` | The oracle's structured completion claims or its reason for stopping. |
| `metrics.json` | The evaluator's verdict plus the path, expected value, actual value, and presence of each assertion target. |
| `state_refs.json` and `states/` | The final state reference and the immutable JSON snapshots from the run. |

Exit codes are `0` for a pass, `1` for a graded failure, `2` for invalid configuration, and `3` for an infrastructure or artifact integrity error. The failure tests exercise each category. The replay uses canonical JSON and logical event order as its comparison data.
